## Penguatan tambahan

Perbaikan juga mencakup beberapa masalah yang terlihat saat pemeriksaan silang:

- Guard `requireActiveUser` diterapkan pada API budget, checklist, kalender, tamu/gift, seserahan, souvenir, vendor, pengaturan WhatsApp, dan manajemen pengguna. Query dan mutasi dibatasi oleh `user_id` serta relasi parent yang sesuai.
- Payload API utama memakai allowlist, validasi tipe/enum, nilai biaya nonnegatif, jumlah positif, serta URL dokumen `http(s)`.
- Fetch kalender memakai request ID dan abort signal agar respons bulan lama tidak mengganti bulan yang sedang aktif.
- Alur logout memeriksa hasil `signOut()`; navigasi sukses hanya dilakukan setelah sign-out berhasil.
- Semua perpindahan yang mengubah batas sesi/status—login, registrasi, logout, pending, rejected, halaman awal, dan guard admin—memakai navigasi dokumen baru agar cache redirect App Router tidak mempertahankan status lama. Halaman rejected juga dapat mengecek status ulang bila admin mengaktifkan kembali akun.
- Validasi gift memperhitungkan tipe gift tersimpan saat PATCH/import parsial, sehingga nilai negatif atau bukan angka tidak lolos untuk gift uang ketika `gift_type` tidak ikut dikirim.
- Berkas environment contoh dan petunjuk setup tersedia. Pemeriksaan akhir menemukan template sempat terisi; `.env.example` sudah dikembalikan menjadi tiga nilai kosong, tetap belum terlacak, dan tidak memiliki riwayat Git. `.env.local` tetap diabaikan serta tidak diubah.

## Langkah eksternal yang masih diperlukan

1. **Cabut token lama.** Buka layanan penerbit token yang sebelumnya dipakai oleh konfigurasi MCP, revoke token lama, lalu buat token baru hanya jika integrasi itu masih dibutuhkan. Simpan token baru di konfigurasi lokal yang tidak terlacak. Bila repository pernah dibagikan, pertimbangkan pembersihan riwayat Git setelah berkoordinasi dengan seluruh pengguna repository; rotasi token tetap wajib karena rewrite history saja tidak menonaktifkan kredensial.
2. **Pertimbangkan rotasi service-role Supabase bila workspace pernah dibagikan.** Nilai itu ditemukan dalam `.env.example` lokal sebelum template dikosongkan. File tersebut belum pernah terlacak Git, jadi tidak ada bukti nilai masuk ke riwayat repository; rotasi tetap disarankan bila workspace, arsip, atau log sesi pernah dibagikan ke pihak lain.
3. **Uji dan terapkan transaksi paket final Supabase.** Terapkan `supabase/migrations/20261017000100_set_vendor_final_package.sql` terlebih dahulu pada database pengujian yang disposable, lalu jalankan `supabase/tests/set_vendor_final_package.sql`. Setelah pemeriksaan ownership, status akun, rollback kegagalan, dan privilege lulus, terapkan migrasi yang sama ke lingkungan produksi melalui proses deployment database. Sampai migrasi tersedia, endpoint pemilihan paket final sengaja mengembalikan 503 agar tidak kembali ke operasi parsial.

Sesudah langkah wajib tersebut, lakukan smoke test terautentikasi pada lingkungan staging untuk login akun aktif/pending/rejected, perpindahan akun pada browser yang sama, import CSV parsial, CRUD kalender pada zona Asia/Jakarta, serta pemilihan paket final vendor. Langkah ini memerlukan akun dan database pengujian sehingga tidak dijalankan terhadap data produksi dalam sesi perbaikan ini.
